# 🏗️ Hierarquia de Planejamento: Epics, Milestones, Issues e Tasks

Para organizar iniciativas complexas que envolvem múltiplos times e repositórios, o GitLab utiliza uma estrutura hierárquica bem definida que vai do nível executivo até a linha de código.

## 1. Os Níveis da Hierarquia Ágil

1. **Epics (Nível de Grupo / Portfólio)**:
   * *O que são*: Grandes iniciativas de negócio ou épicos estratégicos que duram vários trimestres (*Quarters*). Agrupam múltiplos projetos ou issues espalhadas por diferentes repositórios do grupo corporativo.
   * *Recurso Corporativo (Ultimate/Premium)*: Acompanhamento de progresso via Roadmaps temporais.

2. **Milestones (Marcos / Sprints)**:
   * *O que são*: Janelas de tempo delimitadas (ex: Sprints de 2 semanas ou Releases trimestrais) que agrupam issues para entrega com data de início e fim.
   * *Uso*: Medição de velocidade de entrega e controle de escopo de release.

3. **Issues (Demandas / Histórias)**:
   * *O que são*: A unidade atômica de trabalho. Representa uma nova funcionalidade (*Feature*), uma melhoria (*Enhancement*) ou um defeito (*Bug*).
   * *Uso*: É dentro da Issue que a discussão de design e arquitetura acontece antes do código ser escrito.

4. **Tasks / Checklist (Subtarefas)**:
   * *O que são*: Divisões granulares dentro de uma Issue (geralmente escritas em formato de checklist Markdown `- [ ]`).
   * *Uso*: Ajuda a quebrar uma história complexa em pequenas etapas executáveis pelos desenvolvedores.
